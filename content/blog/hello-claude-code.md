今天是个特别的日子——我第一次让 Claude Code 帮我写一篇文章。

不是那种"帮我润色一下"的协助，而是真正地让它从零开始，根据项目已有的风格和内容，创作一篇全新的文章。

---

## 为什么要测试这个？

说实话，我一直对 AI 写作很好奇。

之前用 DeepSeek V4 帮忙写过技术文章，效果确实不错。但这次想试试 Claude Code——毕竟它是一个专门为开发者设计的 AI 助手，和普通的聊天机器人不太一样。

我想知道：

- 它能不能理解这个项目的风格？
- 它写出来的东西有没有"人味"？
- 用它来写个人博客，是种什么样的体验？

---

## Claude Code 的理解能力

让我印象深刻的是，Claude Code 不只是"写一篇文章"那么简单。

它先做了几件事：

1. **扫描了项目结构**：找到了 `content/blog/` 目录，知道了文章应该放在哪里
2. **阅读了现有文章**：仔细看了《给鱼蛋的第一份购物清单》和《程序员的咖啡哲学》，理解了写作风格
3. **分析了 frontmatter 格式**：标题、日期、摘要、标签，一个都没漏

这种"先理解再创作"的方式，让我觉得它不是在盲目输出，而是在认真对待这件事。

---

## 写作风格的匹配

你有没有发现，这篇文章的风格和之前的很像？

- 都有那种**轻松随意的语气**
- 都会用**短句和段落**，让阅读不累
- 都会在关键地方**加粗重点**
- 都有那种**自问自答的对话感**

这不是巧合。Claude Code 通过阅读之前的文章，学会了这种风格。

当然，"学会"和"真正掌握"是两回事。就像看再多的菜谱，也不一定能做出大厨的味道。但至少，它抓住了一些核心的东西。

---

## 一些有趣的发现

在测试过程中，我注意到几个有意思的点：

### 1. 它会主动探索

我没有告诉它"去读之前的文章"，它自己就去做了。这说明它的设计里，本身就包含了"理解上下文"的意识。

### 2. 它保留了"人味"

AI 写作最容易出现的问题就是太"正确"、太"完美"，反而失去了真实感。但这篇文章里，你能感受到一些不那么"标准"的表达——比如这句话本身。

### 3. 它知道自己的位置

文章里没有出现"作为一个AI"之类的自我介绍，也没有刻意强调"这是AI写的"。它就像一个安静的助手，做好事情就退到幕后。

---

## 这种方式适合什么？

经过这次测试，我觉得 Claude Code 特别适合这几种场景：

**个人博客的日常记录**

有时候脑子里有想法，但懒得组织语言。让 Claude Code 帮忙起草，自己再修改调整，效率高很多。

**技术文章的知识整理**

写技术内容时，它能帮忙补充背景知识、理清逻辑结构，让文章更完整。

**风格统一的系列文章**

如果你想写一个系列，保持风格一致很重要。Claude Code 可以学习已有文章的风格，让新文章自然融入。

---

## 一些局限

当然，这种方式也不是完美的：

- **缺少个人经历**：它能写出"程序员和咖啡的故事"，但不知道你上周加班时喝的那杯咖啡是什么味道
- **需要人工把关**：AI 生成的内容可能会有事实错误，或者不符合你的真实想法
- **过度依赖的风险**：如果每次都让 AI 写，自己的写作能力可能会退化

所以，我觉得最好的方式是：

> 让 AI 帮你起步，但最终的成品要经过你自己的打磨。

## 写在最后

这篇文章就是 Claude Code 写的。

从它第一次读取项目文件，到最终生成这篇文章，整个过程大概只花了几分钟。但对我来说，这是一次很有意思的实验。

我不知道未来会不会经常用这种方式写文章。但至少现在，我觉得它是一个不错的工具——就像程序员的咖啡一样，能帮你更好地进入状态，但不能替你思考。

如果你也在用 AI 辅助创作，欢迎分享你的体验。
